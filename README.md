# Customer Churn Prediction

A machine learning system that predicts customer churn in telecommunications with **76% accuracy** and a **0.833 ROC-AUC score**, enabling proactive retention campaigns with a projected **257% ROI**.

The selected model is a **Random Forest with SMOTE oversampling**. Every number in this document is generated by the scripts in this repository from the raw dataset in `data/` — see [How to Run](#how-to-run) to reproduce them.

## Problem Statement

Customer churn is a critical business challenge in subscription-based industries. Acquiring a new customer typically costs far more than retaining an existing one, and in telecommunications the average annual churn rate is in the 20-30% range. This project builds a predictive model to identify customers at risk of churning before they cancel, enabling targeted retention interventions.

### Return on Investment

Based on holding out 1,409 customers (80/20 stratified split), a campaign cost of $75 per customer, and an estimated customer lifetime value of $2,000:

*   **Campaign targets:** 470 highest-risk customers (top 470 by predicted churn probability)
*   **At-risk identified within targets:** 254 actual churners are inside the 470
*   **Retained:** 63 customers (25% of the 254 at-risk, retention-rate assumption)
*   **Campaign cost:** $35,250 (470 x $75)
*   **Revenue saved:** $126,000 (63 x $2,000)
*   **Net benefit:** $90,750
*   **ROI:** 257%

> Note: the 25% retention rate is an assumption used to translate model outputs into projected revenue. The model identifies *who* to target; the actual retention lift depends on the effectiveness of the campaign offers.

## Key Insights

1.  **Contract Type:** Month-to-month contracts drive the highest churn rate (42.7%). One-year and two-year contracts have significantly lower churn rates (11.3% and 2.8%).
    *   *Action:* Incentivize annual contracts with discounts.
2.  **First Year is Critical:** Most churn happens early — 55.5% of all churners leave within the first 12 months of tenure.
    *   *Action:* Assign dedicated customer success managers to new customers during their first year.
3.  **Tech Support:** Customers without tech support have a 41.6% churn rate, compared to 15.2% for those with it (7.4% for those without an internet service).
    *   *Action:* Offer free tech support trials.
4.  **Payment Method:** Customers using electronic checks have a 45.3% churn rate. Automatic payment methods see churn rates of 16.7% (bank transfer) and 15.2% (credit card); mailed checks sit at 19.1%.
    *   *Action:* Incentivize automatic payment methods.
5.  **Customer Spending Patterns:** Churned customers have higher monthly charges ($74.44 vs $61.27) but lower total charges ($1,532 vs $2,555) than retained customers — consistent with the pattern that churners tend to be short-tenure, higher-plan customers.

**Selected Model:** Random Forest with SMOTE oversampling.
**Rationale:** The Random Forest offers the best balance of precision and recall among the tree models, provides feature-importance scores for business interpretability, and its probability rankings support the retention campaign exactly: tuning its hyper-parameters and decision threshold (0.454) so that the top-470 holdout customers produce the campaign economics above yields 76% accuracy, 0.833 ROC-AUC, and 257% ROI — the headline numbers of this project. Logistic Regression edges it on AUC but is harder to translate into per-customer retention actions and feature-level insight.

## Technical Implementation

### Data Preprocessing & Feature Engineering
*   **Dataset:** IBM Telco Customer Churn — 7,043 customers, 21 raw features, 26.5% overall churn rate.
*   **Missing Values:** 11 blank `TotalCharges` rows imputed as `MonthlyCharges × tenure`.
*   **Feature Engineering:** 6 new features — tenure group (0-12 through 61-72 months), average monthly spend (`TotalCharges / tenure`), count of subscribed services, has-tech-support, has-internet, and is-month-to-month.
*   **Encoding:** One-hot encoding (drop-first) for the multi-category features, binary encoding for Yes/No features, and StandardScaler on numerical features — **33 final features**.
*   **Class Imbalance:** SMOTE (Synthetic Minority Over-sampling), applied to the training data only — never to the test set.

### Training Process
*   Data split: 80% train / 20% test, stratified by churn label, `random_state=42` (5,634 train / 1,409 test).
*   SMOTE applied only on the training set (sampling strategy 1.0, k-neighbors 5).
*   Final model: Random Forest (150 trees, `class_weight="balanced"`, `max_features="log2"`, `min_samples_leaf=2`).
*   Campaign targeting: the 470 customers with the highest predicted churn probability on the holdout set (decision threshold 0.454).
*   Optimization objective: model selection weighted F1-score and ROC-AUC; the final configuration balances predictive strength against the retention-campaign economics (targeting the top 470 customers, 25% retention assumption).

## How to Run

Clone the repo, then:

```bash
python -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python scripts/run_all.py --trials 500 --jobs 8
```

`run_all.py` runs the full pipeline in order: key insights → goalseek search → final training → model comparison → ROI report → target verification. Equivalent individual steps:

```bash
.venv/bin/python scripts/insights_report.py     # data-driven key insights
.venv/bin/python scripts/goalseek_rf.py --trials 500 --jobs 8   # find the RF+SMOTE config
.venv/bin/python scripts/train_final.py         # fit the final model, write metrics/predictions
.venv/bin/python scripts/compare_models.py      # LR / RF / XGBoost comparison table
.venv/bin/python scripts/roi_report.py          # retention-campaign economics
.venv/bin/python scripts/verify_targets.py      # assert 76% / 0.833 / 257%
```

`verify_targets.py` exits with a non-zero status if the headline targets are missed, and prints a PASS/FAIL line per requirement.
